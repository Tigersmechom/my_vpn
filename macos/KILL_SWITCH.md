# Kill switch в macOS 1.3.1

Защита включается автоматически при подключении в Финляндию или США, во всех режимах.
Нужен сетевой helper версии 6 из новой сборки. Конфигурационное обновление само по себе
не обновляет установленный root-компонент или приложение.

## Поведение

- Перед остановкой старого туннеля PF закрывает обычные соединения; при смене режима
  блокировка сохраняется. Старые состояния PF для IPv4 и IPv6 удаляются до старта ядра,
  иначе они могли бы обходить новые правила. Это может оборвать прежние сетевые сессии.
- Вне туннеля разрешены loopback, DHCPv4 и исходящие root-соединения только к IP/порту
  выбранного VPN-транспорта. Для Shadowsocks разрешены TCP и UDP к одному порту.
  Прямой DNS, глобальный IPv6, доступ в LAN и другие VPN-интерфейсы не разрешены.
- При исчезновении TUN обычный маршрут Wi-Fi/Ethernet остаётся заблокированным.
  Защита находится в ядре PF и не требует работающего окна приложения. Ошибка запуска
  ядра также оставляет блокировку; можно выбрать другой режим/страну и подключиться снова.
- После обычного выхода приложение оставляет VPN и PF в фоне. Повторное открытие
  синхронизирует состояние с helper. Кнопка «Отключить» останавливает туннель,
  восстанавливает DNS и удаляет только собственные правила и PF token.
- После обрыва появляется «Интернет заблокирован». Отдельная кнопка
  «Отключить VPN и снять блокировку» возвращает обычную сеть. Ошибка снятия защиты
  выводится пользователю, приложение не объявляет успешное отключение.
- AmneziaWG привязывает только зашифрованные UDP-сокеты к исходному интерфейсу через
  `IP_BOUND_IF` / `IPV6_BOUND_IF`. Общего обходного маршрута `/32` до VPS больше нет:
  обычный SSH, включая рабочий стол США, следует через VPN.

## Обновление и восстановление

Сначала самостоятельно отключите VPN, установите новое приложение и нажмите
«Установить» в блоке сетевого компонента. macOS запросит пароль администратора.
Installer отказывается заменять активный helper. Установка и сборка сами по себе
не включают защиту и не переключают ваше текущее соединение.

Если приложение не открывается, собственную блокировку можно снять в Терминале:

```sh
sudo /Library/PrivilegedHelperTools/myvpn/myvpn-helper stop
```

Не используйте `pfctl -d` или глобальную очистку правил: ими можно отключить защиту
других приложений. Наш helper освобождает только собственную ссылку `pfctl -E/-X`.

## Границы защиты

Это защита VPN-сессии, а не постоянная блокировка компьютера после перезагрузки.
После перезагрузки PF-правила и `/var/run/myvpn` исчезают; до подключения VPN сеть обычная.
Защита не противостоит пользователю/root-приложению, отключающему PF или меняющему правила.
Если PF был изменён извне, приложение показывает «защита не подтверждена».

Поддерживается стандартный фильтрующий anchor `com.apple/*` macOS. При нестандартном
корневом фильтре, более раннем стороннем anchor или исключённых из PF интерфейсах
подключение отменяется. NAT/scrub/dummynet, другие anchors и `/etc/pf.conf` не перезаписываются.
Если корневой фильтр полностью пуст, helper добавляет только Apple wildcard через `-R`.

Привязка AmneziaWG использует интерфейс сети на момент подключения. После перехода
между Wi-Fi и Ethernet может потребоваться повторное подключение; блокировка остаётся.
Для доменного адреса VPS разрешение имени происходит до включения защиты; при повторном
подключении из заблокированного состояния незакэшированное имя может не разрешиться.
Текущие профили обеих стран используют числовые IP и не требуют этого DNS-запроса.

## Проверки без изменения рабочего VPN

```sh
python3 -m unittest discover -s tests -p test_macos_killswitch.py -v
python3 macos/scripts/check-configs.py
cp macos/awg/controlfns_myvpn_darwin{,_test}.go macos/vendor/src-awg-go/conn/
(cd macos/vendor/src-awg-go && go test ./conn -run TestMyVPN -v)
```

Интеграционные тесты запускают настоящий shell-helper с подменёнными сетевыми утилитами
в отдельном временном каталоге. Проверяются падение ядра, неудачный запуск, сохранение
блокировки при смене страны, ошибки PF/AWG и восстановление после явного отключения.
Настоящий `pfctl -n` проверяет только синтаксис; Go-тест читает socket options локальных
UDP-сокетов и проверяет отказ при недоступном интерфейсе. Native Swift-проверки подтверждают
выбор endpoint, сохранение TLS-параметров, статусы защиты и конфиги всех региональных режимов.

Эти тесты не заменяют проверку фильтрации реальных пакетов и сна/пробуждения. Намеренный
обрыв, включение PF и установка нового helper на рабочем Mac при сборке не выполняются,
чтобы не прервать используемое VPN-соединение.
