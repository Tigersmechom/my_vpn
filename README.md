# My VPN

Персональные приложения Android и macOS с системным TUN, тестом скорости и зашифрованным
обновлением настроек одной кнопкой. Текущий каталог предлагает Hysteria 2 и AmneziaWG;
Android 1.4.1 и macOS 1.5.1 также поддерживают отдельный резерв VLESS + REALITY по TCP.
Прямая Финляндия по UDP и Hysteria 2 + Salamander убраны из списка подключений.

## Основные подключения

В основном разделе доступны три маршрута, по два протокола в каждом:

| Маршрут | Hysteria 2 | AmneziaWG | Выход в интернет |
|---|---|---|---|
| Испания напрямую | ✓ | ✓ | Испания |
| Испания → Финляндия | ✓ | ✓ | Финляндия |
| Россия (Яндекс) → Испания | ✓ | ✓ | Испания |

На Mac основной раздел называется **«Испания»**. Раздел США сохраняет два режима и кнопку
полного удалённого рабочего стола. На Android каталога США нет. Установленные macOS 1.5.0
и Android 1.4.0 получают этот список без переустановки: через «Обновить конфигурацию» либо
автоматически в открытом приложении без VPN. Номера ревизий: Mac 8, Android 8.
Прежний российский вход удалён; новый вход в Яндекс Облаке — `84.201.168.8`.
У него три варианта: Hysteria 2, AmneziaWG и VLESS + REALITY по TCP. Все выходят через Испанию.
Для третьего варианта на Mac нужна однократная установка 1.5.1: версия 1.5.0
получит новый сервер для двух UDP-режимов, но дополнительные TCP-кнопки не отображает.

Android 1.4.1 поддерживает две отдельные кнопки **«Россия (Яндекс) → Испания · резерв TCP»** и
**«Финляндия · TCP»** и обновляет
встроенное ядро Xray до 26.11.9. Оба режима используют TCP/443; шесть прежних вариантов
сохранены. Итого на Android восемь подключений. Прямая Финляндия добавлена только по TCP. Для появления новой возможности в старом APK нужна одна установка 1.4.1;
дальнейшие совместимые Xray outbounds загружаются через `extraXray` по кнопке обновления. Новый APK сохраняет прежнюю подпись.
При установке более новой сборки её подписанный комплектный профиль применяется офлайн,
если его минимальная ревизия выше сохранённой. История и выбор прежнего режима сохраняются;
уже установленная более новая конфигурация не откатывается.
Исполняемое ядро остаётся частью APK. Старые приложения проверяют новый feed, но
не отображают дополнительные режимы; их прежний каталог продолжает работать.

TCP-вход «Россия → Испания» — отдельная служба `myvpn-tcp-reserve`, изолированная от UDP-пересылки. Она
принимает VLESS + REALITY и отправляет пользовательский трафик через Hysteria 2 в Испанию;
прямого выхода из России для пользовательского трафика нет. Конфиги генерирует
`server/tcp_reserve.py`, systemd-шаблон — `server/myvpn-tcp-reserve.service`. Ключи
передаются генератору приватным JSON, private key REALITY остаётся на сервере.
Вход расшифровывает TCP-туннель и устанавливает отдельное соединение до выхода в Испании.
Ключи REALITY нового входа независимы от выключенного российского VPS.

В Xray-режимах Android DNS обрабатывается внутри TUN: IP-запросы идут по HTTPS через
выбранный прокси; остальные DNS-типы сохраняют пересылку через TCP внутри прокси.
IPv6 остаётся заблокирован, как в предыдущей версии. Сертификаты DoH проверяются,
локального DNS-fallback нет. DNS AmneziaWG остаётся из профиля.

Посредники пересылают исходные зашифрованные UDP-пакеты до выбранного выходного сервера.
Конечный сертификат Hysteria, SHA-256 pin и ключи AmneziaWG принадлежат выходному серверу.
Россия → Испания использует входящие UDP-порты 443 и 8443. Посредник не завершает VPN и
не получает ключей расшифровки. Разрешены только два или три фиксированных назначения.

Оба типа подключения используют UDP. Доступность SSH, ping или одного UDP-пакета
не доказывает работу VPN: перед публикацией проверяются HTTPS, DNS и передача данных
через конкретные режимы. Работа во всех сетях России не гарантируется.

## Сборки

- `dist/MyVPN-1.5.1-macos-arm64.zip` — Apple Silicon, macOS 13+; основа 1.3.0 до kill switch,
  прежний сетевой компонент версии 5.
- `dist/MyVPN-1.4.1-android-arm64.apk` — Android 7+, arm64.
- `dist/MyVPN-1.4.1-android-universal.apk` — несколько архитектур Android.
- `dist/SHA256SUMS.txt` — контрольные суммы.

Сборки персональные и содержат ключи VPN и обновлений, поэтому исключены из Git.
Android сохраняет прежнюю подпись для установки поверх 1.1.0. Mac-приложение подписано
ad-hoc, без нотарификации Apple. Kill switch в эту версию не входит.

После установки поверх старой версии нажмите **«Обновить конфигурацию»**, затем выберите
нужный маршрут и подключитесь. Если предыдущий туннель мешает загрузке, сначала отключите
его. Обновление настроек сохраняет новую конфигурацию для следующего подключения;
работающий туннель не переключается.

## Обновления и маршруты

Публичные `updates/android.json` и `updates/mac.json` содержат только AES-256-GCM ciphertext.
Приватные `config/*-update.json` содержат неизменный HTTPS URL, идентификатор клиента,
ключ AES и минимальную ревизию. Изменять ключ канала при замене сервера не нужно.

Профиль, идентификатор клиента, ревизия, размер и подлинность проверяются до сохранения.
Старые ревизии отклоняются. Данные сохраняются атомарно; сброс восстанавливает последний
проверенный профиль. Исполняемый код через обновления не загружается.

Кнопка обновления заново применяет проверенный каталог даже при той же ревизии, если
локальный профиль был изменён. Автоматическое обновление применяет только новую ревизию,
чтобы не затирать ручные правки каждые пять секунд. Выбор удалённого маршрута заменяется
первым доступным; работающий VPN продолжает использовать свой снимок конфигурации.

В открытом окне приложения при отключённом VPN каждые пять секунд проверяются каталог и
доступность всех режимов выбранной страны. На Android проверяются все строки основного
списка. При уходе в фон, потере фокуса, закрытии/сворачивании окна или подключении VPN
автоматические проверки останавливаются. Долгая проверка завершается до следующей: раунды
не перекрываются. Первое соединение может занять больше пяти секунд.

Зелёная строка — HTTPS прошёл, задержка меньше 250 мс и последние попытки успешны;
жёлтая — высокая задержка, единичный сбой или ещё нет результата; красная — два сбоя подряд
либо ошибка авторизации/сертификата. Рядом указаны задержка, число успешных попыток из
последних пяти и разброс. Проверяется фиксированный `HEAD https://www.google.com/generate_204`
через каждый VPN, без загрузки тела ответа. Отказ контрольного сайта также влияет на оценку.
Цвет не является измерением пропускной способности и не гарантирует работу всех сайтов.

Компонент `health/` использует официальные Hysteria 2 и AmneziaWG в отдельном процессе без
системного TUN, изменения DNS и маршрутов. Соединения сохраняются между раундами;
одновременно идут максимум три запроса. Нагрузка мала, но не нулевая: есть служебный обмен,
шифрование и один короткий запрос на режим. Большие файлы автоматически не скачиваются.
На Android TCP-режим проверяется отдельной службой `:xray_probe`: она выполняет до двух коротких
HTTPS-запросов generate_204, без TUN и скачивания тестовых файлов, и завершается при
паузе. Проверка вынесена из основного процесса, чтобы не смешивать Go runtimes с
AmneziaWG. На Mac 1.5.1 дополнительные режимы проверяются отдельным Xray через локальный
SOCKS и один короткий HEAD-запрос; временные файлы закрыты правами 0600 и удаляются.
При уходе в фон или подключении VPN проверочные процессы останавливаются, системные
маршруты и DNS не меняются. AmneziaWG получает отдельные постоянные peers для проверок каждого устройства и маршрута
(`probeAwg`), поэтому проверки не перехватывают обычные VPN-подключения. Без отдельного
ключа строка остаётся жёлтой. Android передаёт системные корневые сертификаты компоненту;
проверка TLS и SHA-256 pin Hysteria остаётся включённой.

После однократной установки этой версии новые серверы, названия и маршруты Hysteria 2,
AmneziaWG и поддерживаемые встроенным Xray дополнительные режимы появляются из каталога.
Обновление исполняемого ядра потребует нового приложения.

Поле `routes` содержит до восьми записей `{id, title, profile}`. Каждая запись несёт отдельный
профиль подключения существующими ядрами. Вложенные маршруты, повторные ID, пустые
списки протоколов и профили другого устройства отклоняются. Базовый профиль и два маршрута
с двумя протоколами дают шесть кнопок. Mac использует `additionalServers` для отдельной
страны США; Android этот каталог не принимает.

Владелец сначала настраивает серверы и проверяет маршруты. Отдельные ключи проверок
создаются без перезапуска VPN-служб (SSH-адрес выходного сервера берётся из `exitHost` для
маршрута через посредник, иначе из `host`):

```bash
.venv/bin/python tools/prepare_probe_keys.py --only-missing --profiles config/mac.json config/android.json --ssh-key ~/.ssh/myvpn_ed25519
```

Затем публикует профили:

```bash
python3 -m venv .venv
.venv/bin/pip install -r tools/requirements-update.txt
.venv/bin/python tools/publish_updates.py --profile config/android.json --bootstrap config/android-update.json --output updates/android.json
.venv/bin/python tools/publish_updates.py --profile config/mac.json --bootstrap config/mac-update.json --output updates/mac.json
```

Публиковать можно исходники и зашифрованные feeds. `config/*.json` с секретами, `exports/`,
готовые приложения, SSH-ключи и доступ к рабочему столу остаются локальными.

## Сервер

Установка на своём Ubuntu 22.04/24.04 из каталога `server`:

```bash
ENABLE_VLESS=0 bash install.sh
vpnctl profile android
vpnctl profile mac
```

При новой установке можно задать `PUBLIC_HOST`, `AWG_PORT`, `HY2_PORT`, `HY2_OBFS_PORT`.
Существующие серверные и клиентские ключи сохраняются. Дополнительные профили AmneziaWG
для одновременного использования создаются `vpnctl add-awg-device`.

Пересылка двух фиксированных портов на сервере-посреднике:

```bash
python3 udp_relay.py install --listen EDGE_PUBLIC_IPV4 --target EXIT_PUBLIC_IPV4 --listen-ports 443 8443 --target-ports 443 54970
```

Для ВМ за one-to-one NAT дополнительно укажите адрес её сетевого интерфейса:

```bash
python3 udp_relay.py install --listen EDGE_PUBLIC_IPV4 --local-address 10.130.0.30 --target EXIT_PUBLIC_IPV4 --listen-ports 443 8443 --target-ports 443 54970
```

В этом случае DNAT, SNAT и проверки conntrack используют внутренний адрес ВМ;
клиентские профили продолжают подключаться к публичному адресу. Без `--local-address`
поведение прежних серверов сохраняется. Назначения пересылки остаются фиксированными.

Замените параметры адресами и UDP-портами своего выходного сервера. Если `--listen-ports`
не задан, сохраняется прежняя нумерация: 10443, 10444, 10445. Служба `myvpn-udp-relay` восстанавливает правила после
загрузки. Скрипт управляет только собственными цепочками iptables, не очищает остальные
правила и допускает пересылку только на заданные адрес и порты.

## Проверки и сборка из исходников

```bash
.venv/bin/python -m unittest discover -s tests -q
python3 macos/scripts/check-configs.py
cd health && go test -race ./... && cd ..
cd macos && ./build.sh
```

Для проверочного компонента нужен Go 1.26+, для Android также Android NDK 27.2.12479018
(`ANDROID_NDK_HOME` позволяет изменить путь). `health/build.sh` собирает встроенные исполняемые
файлы автоматически при сборке приложений.

Для Android нужны Android SDK и JDK 17; из `android` запустите `./gradlew testReleaseUnitTest assembleRelease`.
Проверки конфигураций не создают TUN. Пользовательское подключение при серверных тестах
не переключается: используются отдельные SOCKS-порты и userspace netstack.
